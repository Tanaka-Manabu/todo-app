# TODO管理システム 要件定義書

**バージョン:** 1.0  
**作成日:** 2026-05-05  
**ステータス:** ドラフト

---

## 1. システム概要

個人がタスクを効率的に管理・追跡するためのTODO管理システム。タスクの作成・整理・進捗管理をシンプルかつ直感的に行えることを目指す。

**技術スタック:** Next.js + TypeScript + Tailwind / Python + FastAPI / MySQL + SQLAlchemy + Alembic / Docker Compose

---

## 3. ユーザーストーリー

### 3.1 タスク管理

**US-01 タスクの作成**
> ユーザーとして、素早くタスクを記録したい。なぜなら、頭の中のToDoを忘れる前にキャプチャしたいからだ。

受け入れ条件:
- タイトルのみ入力すれば1アクションでタスクを保存できる
- 期限・優先度・カテゴリはオプションとして後から追加できる
- 作成直後にタスク一覧に表示される

---

**US-02 タスクの完了**
> ユーザーとして、タスクを完了マークしたい。なぜなら、達成感を得つつ残りのタスクに集中したいからだ。

受け入れ条件:
- チェックボックス1クリックで完了状態に切り替わる
- 完了タスクは一覧から視覚的に区別される（取り消し線・グレーアウト）
- 誤操作した場合は同じ操作で未完了に戻せる

---

**US-03 期限切れタスクの把握**
> ユーザーとして、期限切れタスクをひと目で確認したい。なぜなら、見落としによるタスクの放置を防ぎたいからだ。

受け入れ条件:
- 期限超過タスクは赤色でハイライト表示される
- 「期限切れ」フィルタで一覧を絞り込める
- 期限の24時間前にメール通知が届く

---

**US-04 カテゴリによる整理**
> ユーザーとして、カテゴリごとにタスクを整理したい。なぜなら、異なる用途のタスクが混在すると集中できないからだ。

受け入れ条件:
- カテゴリを作成・編集・削除できる
- タスク一覧をカテゴリで絞り込める
- カテゴリ別のタスク件数が表示される

---

**US-05 タスクの検索**
> ユーザーとして、特定のタスクをキーワードで素早く探したい。なぜなら、タスク数が増えるとスクロールして探すのが困難になるからだ。

受け入れ条件:
- 検索ボックスに入力すると即時（インクリメンタル）に結果が絞り込まれる
- タイトルと詳細テキスト両方を検索対象とする
- 検索結果がゼロの場合は空状態のメッセージを表示する

---

**US-06 サブタスクによる細分化**
> ユーザーとして、タスクをサブタスクに分割したい。なぜなら、作業の粒度を下げて進捗を可視化したいからだ。

受け入れ条件:
- タスクに対して複数のサブタスクを追加できる
- サブタスクの完了数 / 合計数が親タスクに表示される（例: 3/5）
- 全サブタスク完了時に親タスクを完了にするか確認プロンプトが表示される

---

**US-07 データのエクスポート**
> ユーザーとして、タスクデータをCSVでエクスポートしたい。なぜなら、外部ツールで集計・レポート作成に活用したいからだ。

受け入れ条件:
- フィルタ条件を適用した状態でエクスポートできる
- CSVには全フィールド（ID・タイトル・状態・優先度・期限・カテゴリ・タグ）が含まれる
- ダウンロード完了時にトースト通知が表示される

---

### 3.2 ユーザー管理

**US-08 新規アカウント登録**
> 新規ユーザーとして、メールアドレスとパスワードでアカウントを作成したい。なぜなら、自分専用の環境でタスクを管理したいからだ。

受け入れ条件:
- メールアドレス・パスワード・パスワード確認を入力して登録できる
- パスワードは8文字以上、英数字混在を必須とする
- 登録後に確認メールが送信され、リンクをクリックするとアカウントが有効化される

---

**US-09 パスワードリセット**
> パスワードを忘れたユーザーとして、メール経由でパスワードをリセットしたい。なぜなら、アカウントに再度アクセスしたいからだ。

受け入れ条件:
- メールアドレスを入力するとリセット用URLが送信される
- リセットリンクの有効期限は60分とする
- 新しいパスワード設定後は全セッションが無効化される

## 4. 非機能要件

### 4.1 パフォーマンス

| 要件ID | 項目 | 基準値 |
|--------|------|--------|
| NF-01 | ページ読み込み時間 | 初回表示 2秒以内（LCP）、操作後の画面更新 500ms以内 |
| NF-02 | 検索応答時間 | インクリメンタル検索の結果表示 300ms以内 |
| NF-03 | 同時接続ユーザー | 100ユーザーの同時接続で性能劣化なし |
| NF-04 | タスク件数上限 | 1ユーザーあたり10,000件のタスクを保持しても性能劣化なし |

### 4.2 セキュリティ

| 要件ID | 項目 | 基準値 |
|--------|------|--------|
| NF-05 | 認証 | JWT + リフレッシュトークンによるセッション管理 |
| NF-06 | パスワード保管 | bcrypt（コストファクター12以上）でハッシュ化して保管 |
| NF-07 | 通信暗号化 | 全通信をHTTPS（TLS 1.2以上）で暗号化 |
| NF-08 | 入力バリデーション | SQLインジェクション・XSSを防ぐサーバーサイドバリデーション |
| NF-09 | レートリミット | ログインAPIは1IPあたり10回/分を上限とする |
| NF-10 | データ分離 | ユーザーは自分のデータのみ参照・操作可能 |

### 4.3 可用性・信頼性

| 要件ID | 項目 | 基準値 |
|--------|------|--------|
| NF-11 | 稼働率 | 99.5%以上（月間ダウンタイム 約3.6時間以内） |
| NF-12 | データバックアップ | 日次自動バックアップ、7世代保持 |
| NF-13 | 障害復旧目標 | RTO: 4時間以内、RPO: 24時間以内 |

### 4.4 ユーザビリティ

| 要件ID | 項目 | 基準値 |
|--------|------|--------|
| NF-14 | レスポンシブ対応 | スマートフォン（375px以上）〜デスクトップ（1440px）で正常表示 |
| NF-15 | ブラウザサポート | Chrome・Firefox・Safari・Edgeの最新2バージョン |
| NF-16 | アクセシビリティ | WCAG 2.1 レベルAA準拠（キーボード操作・スクリーンリーダー対応） |

### 4.5 保守性・開発

| 要件ID | 項目 | 基準値 |
|--------|------|--------|
| NF-17 | テストカバレッジ | ユニットテスト80%以上 |
| NF-18 | APIドキュメント | OpenAPI 3.0形式でAPI仕様を管理する |
| NF-19 | ログ | エラーログはレベル別（ERROR/WARN/INFO）に構造化ログで出力する |
| NF-20 | デプロイ | CI/CDパイプラインによるゼロダウンタイムデプロイ |

## 5. 用語定義

| 用語 | 定義 |
|------|------|
| タスク | ユーザーが管理する個々の作業単位 |
| サブタスク | タスクに紐づく子タスク |
| カテゴリ | タスクをグループ化するラベル |
| タグ | 複数カテゴリに横断的に付与できるキーワードラベル |
| 優先度 | タスクの重要度（高・中・低） |
| 論理削除 | データベースから物理削除せず「削除済み」フラグを立てる方式 |
